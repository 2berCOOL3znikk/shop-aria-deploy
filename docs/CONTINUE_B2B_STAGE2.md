# Промпт для продолжения

Последний этап **V25 готов**: WooCommerceReader.currency() читает строго `data/currencies/current`; WooCatalogImporter проверяет код до/после полного чтения. Код и currencyConfirmedAt сохраняются атомарно со снимком, при ошибке/смене кода сохраняется прежний каталог. В UI магазинов и строках цен показана валюта, неизвестная не выдумывается; API цен — десятичные строки. Старые снимки не пересчитываются, валюта заказов не используется, FX/внешняя запись/AI для внешнего каталога не включены. Валютную часть не начинай заново. Следующий приоритет — page checkpoints/крупные каталоги и настоящее WooCommerce-окружение с live E2E; затем безопасное обогащение внешнего каталога для Smart Pricing.

Последний этап **V24 уже готов**: StoreWebhookService, StoreWebhookReceiver/Receipt, WooWebhookController, подписанная постоянная inbox и интерфейс «Мои магазины → Уведомления». HMAC-SHA256 по исходным байтам, дедуп SHA256 тела на поколение/ресурс, отдельный одноразовый секрет, отзыв адресов, асинхронная передача inbox → StoreSyncQueue. Исходное тело и контакты не сохраняются. Не создавай webhook inbox или очередь заново. POST приёма — единственный публичный callback; остальные настройки ADMIN. Тест проверяет быстрый приём при заблокированной строке магазина.

Валюта каталога подтверждается V25. Следующий приоритет: page checkpoints/крупные каталоги, настоящее WooCommerce-окружение и live E2E. Затем — обогащение и привязка внешних снимков к Smart Pricing с отдельными магазинными политиками/согласиями. Для публичного пилота нужны ingress rate limits/retention и egress/DNS pinning. Не выдавай локальную подписанную HTTP-проверку за подключение настоящего WooCommerce. Сохрани ограничение на внешнюю запись до настоящих проверок и разрешения владельца.

Последний этап V23 — StoreSyncTask/StoreSyncQueue/StoreSyncWorker. Интерфейс уже ставит CHECK/SYNC/ORDERS в постоянную очередь; есть 3 попытки, аренда 5 минут, поколения, защита старого исполнителя до/после импорта, отмена при смене ключей/отключении и статусы/повтор в карточке. Не создавай эту очередь заново. Webhook inbox добавлена V24; далее page checkpoints/крупные каталоги, валюта каталога и настоящий WooCommerce E2E. Настоящая очередь проверяется scripts/store-queue-restart.cjs (prepare → реальный рестарт preview → verify).

Последнее продолжение — V22. Уже реализованы WooOrderImporter/StoreOrderSnapshot и отдельный экран «Мои магазины → Заказы»: импорт без контактов покупателей, чтение статусов/валют/сумм/возвратов/дат UTC, повтор без дубликатов, запрет старого статуса поверх свежего, сохранение снимка при ошибке, история ORDERS. Локальные заказы/склад/AI не меняются. Текущую реализацию заказов не начинай заново. Следующий приоритет: постоянная очередь внешнего импорта/checkpoints, подписанная webhook inbox, настоящий WooCommerce E2E; затем обогащение каталога и отдельные разрешения/политики AI. Валюта заказа известна из источника; валюта каталога пока не подтверждается и не выводится из заказов автоматически. Подробности и проверки — docs/B2B_STAGE2.md.

Продолжай ARIA в `codex/production-foundation`. Сначала прочитай `docs/B2B_STAGE2.md`, `docs/B2B_TRANSITION.md` и git log/status. Не повторяй готовые silo tenancy V19, SaaS workspace/stores UI и V20. Сохрани витрину и старые модули. Главная: `/control.html#workspace`, магазины: `#stores`.

Уже есть ConnectedStoresService/Controller, IntegrationVault, WooCommerceReader, WooCatalogImporter, StoreSnapshot, StoreSyncRun, stores.js/saas.css и scripts/stores-e2e.cjs. V21 добавляет родительский ID вариации и историю завершённых обновлений. WooCommerce читает простые продукты и вариации, сохраняет стабильные ID и прежний каталог при ошибке чтения; внешняя запись/AI пока запрещены. Есть серверный allowlist доменов, шифрование, версии, аудит и отключение. `.env.integrations.local` и `.env.openrouter.local` исключены из Git: не выводи значения и не создавай новые ключи поверх существующих.

Приоритет: подписанная постоянная webhook inbox, checkpoints отдельных страниц и подтверждение валюты каталога. Уже выполненные очередь/заказы/пагинацию/вариации/сохранение ID и экран истории не переписывай. Получить/подготовить настоящее тестовое WooCommerce-окружение без платных сервисов. HTTP mocks не считать внешним E2E. Отдельно протестированы повтор без смены ID и ошибки чтения с сохранением прежнего снимка; это контрактный интеграционный тест, не настоящий WooCommerce.

Затем отдельный контролируемый pipeline внешних снимков к Smart Pricing с подтверждаемой себестоимостью/партиями, разрешениями и политиками именно магазина. Не вставляй отсутствующие сроки/закупку как факты и не смешивай внешние остатки с локальным POS/FEFO. Ценовые записи включать лишь после отдельных реальных E2E и согласия владельца. Защиту исходящих запросов дополнить egress/DNS pinning до production.

Проверить UI создания компании через безопасный локальный provisioning, роли OWNER/STAFF и Impact opt-in. Продолжать монохромный B2B UX. Все доступные функции должны иметь работающий интерфейс. Повторить Java-тесты и stores-e2e; поправить прежние E2E для новой скрываемой навигации, затем проверить регрессии. Сохранять коммиты и push только рабочей ветки. Не менять main/production-базу/основной Render и не подключать платные ресурсы.
