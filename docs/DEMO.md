# Демонстрация ARIA

## Панель администратора

Обзор открывает только свои показатели. Кнопки задач сразу включают фильтр просроченных партий, критических сроков или минимального остатка. Остаток товаров вычисляется по пригодным партиям на момент запроса, даже если фоновый пересчёт отключён.

У товаров и партий есть фильтры, сортировка и страницы по 10/25/50 строк. Заказы фильтруются по статусу; поиск по покупателю, адресу, номеру, сохранённому названию или SKU выполняется сервером. «Подробнее» открывает состав с ценами при заказе и датой отправки. После изменения статуса текущий фильтр сохраняется.

Журнал загружает всю историю постранично, а не только последние 100 событий. Ищите сотрудника, действие, объект или причину. Ошибка одного раздела не мешает открыть другой. При закрытии изменённой формы можно оставить её открытой с введёнными данными или подтвердить закрытие без сохранения. На телефоне таблицы прокручиваются горизонтально.

## Основной сценарий

1. Запустите из backend на Java 21. Войдите admin@aria.shop / admin123 в локальном демо. Для опубликованного сервиса используйте свои учётные данные.
2. Поставщики → Добавить поставщика. Укажите название и контакты. У связанного поставщика сохраняется история; вместо удаления отключайте «Активен».
3. Товары → Добавить товар. Пример: SKU MILK-DEMO, название «Молоко 1 л», категория «Продукты», цена 1000 ₸, единица «шт», минимум 5. Фото можно загрузить отдельной кнопкой (JPEG/PNG до 5 МБ).
4. Склад и партии → Принять партию. Выберите товар, поставщика, номер LOT-001, дату сегодня, срок через 5 дней, количество 10, закупку 800 ₸. У продуктов дата годности обязательна. Для второй поставки используйте другой номер партии и её собственный срок.
5. Каталог показывает товар с остатком 10. Поиск работает по названию, SKU, категории и описанию.
6. Цены и скидки → выберите товар. При 21% показывается убыток и кнопка применения недоступна. При 20% цена 800 ₸, прибыль 0 ₸, применение разрешено после ввода причины. При 10% цена 900 ₸ и прибыль 100 ₸ до расходов. Рекомендации 15/30/50% ограничиваются закупкой; это правило пилота, а не гарантия спроса.
7. В отдельном окне войдите покупателем. Добавьте две единицы, укажите адрес, оформите заказ. Убедитесь, что цена соответствует скидке. В профиле появится заказ. В панели остаток уменьшится, а журнал покажет партии, из которых товар списан.
8. Заказы → отмените новый заказ с причиной. Остаток вернётся в те же партии; повторная отмена невозможна. После отправки доступно подтверждение доставки, отмена из этого состояния не допускается.
9. Социальная полка в Control → опубликуйте 2 единицы с датой выдачи не позже срока партии. Весь SKU временно удерживается от обычной продажи. Это ограничение пилота явно показано в форме.
10. Войдите фондом fund@aria.shop / fund123. Отправьте заявку на проверку. В разделе «Анализы и документы» администратор подтверждает организацию. Фонд бронирует предложение и скачивает акт.
11. В Control подтвердите фактическую выдачу с причиной, только после реальной проверки товара и подписей. Склад уменьшается на 2; статус «Передан». Повторная выдача отклоняется. До подтверждения резерв можно отменить. После срока выдачи подтверждение блокируется.
12. Откройте журнал и сводку Intelligence. Без серверного ключа будет показан режим правил с явным пояснением.

Локальная H2 сохраняет данные в рабочей папке. Для новой демонстрации используйте другую тестовую базу; не включайте сброс данных в рабочем магазине.

## Настройки категорий

Откройте «Настройки правил». Общее правило * применяется, если отдельного правила категории нет. Например, для «Продукты» задайте предупреждение 20 дней и 12%, критический срок 2 дня и 25%, экстренный срок 0 дней и 45%, минимальную маржу 10%. Для товара 1 000 / 800 ₸ система ограничит предложение 11%. Сохранение настройки само не изменяет цену: скидка подтверждается в разделе цен. Для возврата к общим параметрам используйте «Наследовать общее».
