Не выдавать ручное изменение цены за решение модели. Режим RECOMMEND и отдельные согласия сохранены. Перед новой отправкой проверять сохранённый AI: повторная проверка использует существующий ответ без расходования бюджета.

Общий бюджет/согласие компании + отдельное согласие магазина; реальный Java Engine; отсутствие данных явно блокирует автоизменение; AUTOPILOT требует разрешений, категории, достаточной истории, прохождения Java-ограничений и отсутствия запроса подтверждения от модели. Тестовые ответы модели в JUnit — только проверки безопасности, не доказательство live-автопилота.

## Ограничения безопасности

Не менять main, production Render и рабочую БД. Никаких платных ресурсов/моделей, ключей в Git, сброса дневного бюджета или включения разрешений других компаний. Существующие `.env.*`, `data/preview` и `data/woocommerce` сохранять. Последнее разрешение владельца распространяется только на `woo-e2e`.

Проверять готовое по фактическим evidence и CI; не повторять полный E2E с новыми скидками без изменения затронутой логики. `e2e.cjs` — мутирующий сценарий только учебного WooCommerce, предыдущие прогоны сохраняются в архиве. `engine-ui-e2e.cjs` нельзя повторять после настоящего AI как тест «все source=ENGINE»: для persisted AI использовать отдельную проверку.

Внешний REST не даёт распределённой атомарной блокировки с чужими ценовыми роботами: текущая реализация проверяет состояние до и после записи. Учитывать это при коммерческой публикации; автоматический откат не добавлен намеренно. Подтверждённое чтение/запись и восстановление не равны полной коммерческой готовности всего ARIA.
