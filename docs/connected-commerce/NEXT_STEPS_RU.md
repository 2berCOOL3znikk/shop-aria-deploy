`evidence/woocommerce-e2e.json`: UI-мастер, настоящий REST, вариации, KZT/остатки, заказы, реальные WooCommerce webhooks, дедупликация, подтверждённая запись 1350 → 1215 ₸ без списания, потерянный ответ вариации и сверка без повторного PUT, реальный сбой PHP и восстановление импорта.

`evidence/connected-live-ai*.json`: настоящий OpenRouter через UI. Владелец отдельно разрешил AI **только для этой учебной компании**. Бесплатная модель выбрала KEEP 1215 ₸. Не выдавать ручное изменение цены за решение модели. Режим RECOMMEND и отдельные согласия сохранены. Перед новой отправкой проверять сохранённый AI: повторная проверка использует существующий ответ без расходования бюджета.

Общий бюджет/согласие компании + отдельное согласие магазина; реальный Java Engine; отсутствие данных явно блокирует автоизменение; AUTOPILOT требует разрешений, категории, достаточной истории, прохождения Java-ограничений и отсутствия запроса подтверждения от модели. Тестовые ответы модели в JUnit — только проверки безопасности, не доказательство live-автопилота.

## Ближайшая работа

1. RU/EN завершены для оболочки, 23 административных разделов и основных клиентских страниц. Явные ключи сохраняют исходные названия, характеристики и объяснения. Проверены формы, ошибки, 390/768/1440 px, тёмная тема, помощник, корзина и отдельная витрина 8087. Доказательства и поддержка словаря — `../localization/README_RU.md`. Не возвращать автоматический перевод DOM и не повторять успешные проверки без затронутых изменений.
2. Проверить категорийные формы товара: не предлагать пищевые характеристики текстилю; не выдумывать GTIN, состав и сроки партий. Новую архитектуру товара без необходимости не создавать.
3. Сделать понятное самостоятельное создание компании либо довести управляемое оператором подключение до явно обозначенного продукта. Сейчас одна компания = отдельные процесс и БД; кнопка смены названия не создаёт компанию.
4. Реальный внешний WooCommerce требует домена/доступов владельца и публичного HTTPS для webhooks. Ключи не просить в чат. Не называть локальную установку проверенным магазином реального предпринимателя.
5. Проверить на реальной достаточной истории AUTOPILOT: не менять даты учебных заказов ради мнимого коммерческого прогноза; не форсировать модель на скидку, если она выбирает KEEP.

## Ограничения безопасности

Не менять main, production Render и рабочую БД. Никаких платных ресурсов/моделей, ключей в Git, сброса дневного бюджета или включения разрешений других компаний. Существующие `.env.*`, `data/preview` и `data/woocommerce` сохранять. Последнее разрешение владельца распространяется только на `woo-e2e`.

Проверять готовое по фактическим evidence и CI; не повторять полный E2E с новыми скидками без изменения затронутой логики. `e2e.cjs` — мутирующий сценарий только учебного WooCommerce, предыдущие прогоны сохраняются в архиве. `engine-ui-e2e.cjs` нельзя повторять после настоящего AI как тест «все source=ENGINE»: для persisted AI использовать отдельную проверку.

Внешний REST не даёт распределённой атомарной блокировки с чужими ценовыми роботами: текущая реализация проверяет состояние до и после записи. Учитывать это при коммерческой публикации; автоматический откат не добавлен намеренно. Подтверждённое чтение/запись и восстановление не равны полной коммерческой готовности всего ARIA.
