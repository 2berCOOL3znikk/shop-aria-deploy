# B2B-кабинет и магазины — 30.10.2026

Открыть: http://127.0.0.1:8084/control.html#workspace; магазины: #stores. Доступы — `data/preview/access.txt`. Это локальный preview, не обновление основного Render.

Работает: монохромный кабинет, обе темы, мобильное меню, главная с фактическими числами, изменение названия бизнеса; добавление/открытие/обновление/отключение демо-магазина; каталог из существующих Product. Сложные старые инструменты сохранены в дополнительной навигации. Существующая компания не пересоздаётся.

WooCommerce: форма магазина и ключей, AES-256-GCM на сервере, проверка доступа GET wc/v3/products, пагинация до 1000 **простых** товаров, сохранённые снимки цен/доступного количества, повтор без дубликатов, ошибки, история операций в аудите, удаление локальных доступов при отключении. Нет обратной записи. Учёт заказов/вариаций, webhooks, полноценный StoreConnector и передача внешних снимков в AI пока не закончены. Валюта не подтверждается по отсутствующему полю; себестоимость/партии/сроки не выдумываются.

Каждый магазин в изолированной БД компании. Свои AI-политики на внешний магазин ещё не реализованы: внешние снимки не становятся Product и не управляются общим автопилотом. Сохранённая внешняя цена не означает изменение цены в WooCommerce.

## Настройка доступа

- Локально создан и исключён из Git `.env.integrations.local`. Значение ARIA_INTEGRATION_ENCRYPTION_KEY — Base64 32 случайных байтов. Существующий файл сохраняется. Его нужно защищённо резервировать вместе с данными; смена/потеря ключа требует повторного ввода доступов. На Render файл не используется как надёжное хранилище: понадобится секретная переменная сервиса, пока production не настраивался.
- ARIA_WOO_ALLOWED_HOSTS — одобренные домены через запятую без схемы. По умолчанию список пуст. HTTPS/443, без пользовательских данных в URL, локальные/private адреса и редиректы запрещены. Домен должен контролироваться владельцем; для production дополнительно нужен сетевой контроль egress против DNS rebinding.
- WooCommerce → Settings → Advanced → REST API: ключ **Read**. Сохранить через «Мои магазины → Настроить», затем «Проверить доступ» и «Синхронизировать». Ключи после сохранения не возвращаются браузеру.
- Отключение удаляет ключи из ARIA, сохраняет историю/снимки. Сам ключ также нужно отозвать в WooCommerce.
- Shopify/Kaspi не изображаются подключёнными. CSV цен конкурентов остаётся отдельным существующим модулем; CSV собственного каталога ещё не реализован.

Официальный формат: [WooCommerce REST API](https://developer.woocommerce.com/docs/apis/rest-api/). Проверки с mock HTTP — контрактные, не настоящий WooCommerce E2E. Действительные credentials владельца отсутствуют; Docker/PHP для локального WordPress ранее не обнаружены.

## Проверки и воспроизведение

Java: `./mvnw.cmd test`; отдельная PostgreSQL через ARIA_TEST_DATABASE_* / ARIA_TEST_FLYWAY=true / ARIA_TEST_SCHEMA_MODE=validate. V20 добавляет снимки и защищённые доступы, V1–V19 не меняются. Браузер: `node scripts/stores-e2e.cjs` с ARIA_PLAYWRIGHT_MODULE, Edge и запущенным локальным preview. Создаёт проверочный WooCommerce с запрещённым доменом, затем отключает его; не отправляет ключи во внешний сервис. Проверяет настоящий демо-каталог, формы, отказ соединения, отсутствие секретов в ответах, обе темы и 11 основных разделов на 1440/390 px. Артефакты: `target/e2e/stores-report.json`, `saas-*.png`, Java XML в `target/surefire-reports`.
