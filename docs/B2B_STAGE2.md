# B2B-кабинет и магазины — 30.10.2026

**V25 — валюта каталога.** При полном обновлении ARIA читает официальный GET `wc/v3/data/currencies/current` до и после товаров/вариаций. Поддерживается корректный трёхбуквенный код; символы/HTML из ответа не отображаются. Если код меняется, отсутствует или доступ отклонён, импорт не заменяет прежние цены, валюту и отметку подтверждения. Валюта заказов не является источником валюты каталога. Старые записи не получают код задним числом.

В «Моих магазинах» показаны код последнего успешного снимка и время подтверждения; рядом с каждой ценой — собственная сохранённая валюта. Старые неизвестные значения явно подписаны. Демо-каталог остаётся KZT по существующему контракту ARIA. Цены внешнего каталога в API возвращаются десятичными строками. Никакой конвертации, изменения внешних цен или включения AI-записи не выполняется. Проверка валюты входит в прежние лимиты запросов/времени импорта и применяется атомарно со снимком.

Источник: [WooCommerce — Retrieve current currency](https://woocommerce.github.io/woocommerce-rest-api-docs/#retrieve-current-currency). Поддерживается стандартный REST API; мультивалютные плагины требуют отдельной реальной проверки. Чтение одинакового кода до/после не превращает REST-пагинацию в атомарный снимок базы WooCommerce. Настоящий внешний E2E пока не выполнен.

**V24 — подписанные уведомления WooCommerce.** «Мои магазины → Уведомления»: включить приём, один раз скопировать отдельную подпись, перенести адреса товаров/заказов и Secret в WooCommerce → Settings → Advanced → Webhooks. Секрет хранится зашифрованно; GET его не возвращает, поле очищается при закрытии окна. Смена адресов/подписи отзывает предыдущие. Отключение магазина и смена REST-ключей также отзывают приём; после этого webhook-настройку нужно создать заново. Локальный preview не доступен внешнему WooCommerce, требуется отдельный HTTPS-стенд. Создание webhook на стороне WooCommerce вручную не требует выдачи ARIA ключа с правом записи.

Приём проверяет Base64 HMAC-SHA256 **исходных байтов**, размер до 2 МБ и минимальную форму события. Неверная подпись → 401, отозванный приём → 410, старый адрес после ротации → 404. Неподписанный формовый `webhook_id=N` допускается только как безвредный activation ping: нет записи события, задания или отметки успешного соединения. Подписанные события сохраняются в inbox как PENDING, затем передаются в постоянную очередь. Дубликаты по поколению/ресурсу/SHA256 тела получают 204, не создают новую работу. Header Delivery-ID не используется как доказательство уникальности; заголовки Topic/Source не являются основанием доверия. Адрес определяет разрешённый ресурс, тело не применяется к ценам/складу.

В inbox нет исходного JSON, контактов или ключей: только хеш, размер, ресурс, поколение, время и ссылка на задачу. Сначала commit inbox, потом ACK/пробуждение. Диспетчер связывает до 100 событий одной компании с задачами в транзакции. Подтверждение приёма **не означает**, что внешний импорт уже выполнен. Если адрес отозван до передачи — CANCELLED; уже созданные задачи сохраняются (полное отключение магазина отменяет их). Ожидающие события обрабатываются при старте приложения. Приём не ждёт долгого импорта магазина: блокировка и FK относятся к receiver, не к занятой строке магазина. Сетевые/DB-ошибки не превращаются в ложный успех.

История показывает последние 20 событий. Настоящий WooCommerce E2E по-прежнему не выполнен. До публичного пилота остаются проверка настоящего WordPress/WooCommerce, ограничения входящего трафика на периметре, политика хранения inbox, page checkpoints, egress/DNS-защита и отдельные AI-политики внешнего магазина. Платные ресурсы и production не изменялись. Протокол: [WooCommerce webhooks](https://woocommerce.github.io/woocommerce-rest-api-docs/#webhooks).

Продолжение V23: кнопки проверки доступа, каталога и заказов создают **сохраняемую задачу**, затем исполнитель выполняет чтение в фоне. В карточке магазина видны очередь, выполнение, ожидание повтора, успех/ошибка и кнопка повтора после исчерпания попыток. Активный экран перечитывает статус ограниченное время (до минуты), не отправляет постоянные пинги. Окно можно закрыть; задача остаётся в PostgreSQL.

Очередь: одна строка на магазин/операцию CHECK/SYNC/ORDERS; повтор до старта объединяется, новый запрос во время работы сохраняет следующее поколение. Claim фиксируется отдельной транзакцией, аренда — 5 минут, до 3 попыток, интервалы повторов 2/4 минуты. Истёкшая аренда восстанавливается после запуска; старый исполнитель проверяется **до и после импорта** в общей транзакции, не может сохранить результат после отзыва/замены задачи. Смена ключей и отключение магазина отменяют ожидающую работу. Это только чтение, без внешней записи и AI-автопилота.

Задания обрабатываются при запуске и по сохранённым срокам, пока процесс работает. Во сне Render Free действий нет; после пробуждения/запуска работа возобновляется, RUNNING после аварии может ждать истечения аренды. Искусственные HTTP-пинги и платный планировщик не создавались. Legacy `/check`, `/sync`, `/orders/sync` сохранены как синхронные административные API; новый интерфейс использует `/tasks`.

Ограничение: checkpoints отдельных страниц ещё нет — после прерывания повторяется полное ограниченное чтение. Благодаря сохранению внешних ID и атомарному применению повтор не дублирует карточки и заказы. Webhook inbox и настоящий WooCommerce E2E пока не реализованы. Внутренние ошибки БД откатывают импорт; подробности исключения не возвращаются клиенту.

Проверка перезапуска: `node scripts/store-queue-restart.cjs prepare`, реальная остановка/запуск только preview, затем `verify`. Создаётся проверочный магазин без ключей; реальная ошибка чтения фиксируется в RETRY, после рестарта проверяется тот же ID/число попыток и отмена при отключении. Отчёт: `target/e2e/store-queue-restart-report.json`. Внешний HTTP не вызывается. Скрипт допускает только локальный адрес из preview-конфигурации.

Продолжение V22: **«Мои магазины → Заказы → Обновить заказы»**. Отдельные сохранённые снимки WooCommerce: внешний ID, статус, валюта, суммы/возвраты, даты UTC и позиции с ID товаров/вариаций. Контакты, адреса, customer ID, заметки, имена покупателя и произвольные поля позиций не сохраняются и не передаются AI. Текущие названия позиций берутся из импортированного каталога; удалённый товар остаётся несопоставленным без выдуманного ID. Денежные суммы возвращаются строками без потери десятичной точности.

Заказы обновляются отдельно от каталога. Читаются до 1000 заказов/10000 позиций за запуск; в окне отображаются последние 100 сохранённых записей. Это не гарантированно полная история большого магазина. Сохранённые записи не удаляются лишь потому, что отсутствовали в следующем ответе. Повтор сохраняет ID, старая date_modified_gmt не перезаписывает более свежую запись; отсутствие корректной даты изменения отклоняет импорт. Ошибка чтения/валидации сохраняет прежние данные. Сумма заказа включает начисления источника и не называется выручкой локальной отгрузки. Сумма возвратов — по записям refunds; отсутствие списка означает неизвестное значение.

V22 не создаёт локальные Order/InventoryLot, не списывает склад, не меняет внешние статусы/цены и не разрешает AI-действия. Отдельные lastOrdersSync/lastOrdersError не стирают ошибку каталога. История включает операцию ORDERS; поддерживается прежний журнал. Импорт всё ещё синхронный, без checkpoint/восстановления после падения. Настоящий внешний E2E остаётся незавершённым. Спецификация: [WooCommerce order properties](https://woocommerce.github.io/woocommerce-rest-api-docs/#order-properties).

Спецификация вариаций: [WooCommerce v3](https://woocommerce.github.io/woocommerce-rest-api-docs/#product-variations).

## Настройка доступа

- Локально создан и исключён из Git `.env.integrations.local`. Значение ARIA_INTEGRATION_ENCRYPTION_KEY — Base64 32 случайных байтов. Существующий файл сохраняется. Его нужно защищённо резервировать вместе с данными; смена/потеря ключа требует повторного ввода доступов. На Render файл не используется как надёжное хранилище: понадобится секретная переменная сервиса, пока production не настраивался.
- ARIA_WOO_ALLOWED_HOSTS — одобренные домены через запятую без схемы. По умолчанию список пуст. HTTPS/443, без пользовательских данных в URL, локальные/private адреса и редиректы запрещены. Домен должен контролироваться владельцем; для production дополнительно нужен сетевой контроль egress против DNS rebinding.
- WooCommerce → Settings → Advanced → REST API: ключ **Read**. Сохранить через «Мои магазины → Настроить», затем «Проверить доступ» и «Синхронизировать». Ключи после сохранения не возвращаются браузеру.
- Отключение удаляет ключи из ARIA, сохраняет историю/снимки. Сам ключ также нужно отозвать в WooCommerce.
- Shopify/Kaspi не изображаются подключёнными. CSV цен конкурентов остаётся отдельным существующим модулем; CSV собственного каталога ещё не реализован.

Официальный формат: [WooCommerce REST API](https://developer.woocommerce.com/docs/apis/rest-api/). Проверки с mock HTTP — контрактные, не настоящий WooCommerce E2E. Действительные credentials владельца отсутствуют; Docker/PHP для локального WordPress ранее не обнаружены.
