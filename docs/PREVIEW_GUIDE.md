# Как открыть и проверить новую ARIA

Этот стенд работает только на этом компьютере. Это существующий ARIA Shop из ветки `codex/production-foundation`, отдельная база PostgreSQL с проверочными данными. Основной сайт Render и база Neon не переключаются.

## Открыть

1. В папке `backend` дважды нажмите **Start-ARIA-Preview.cmd**. Дождитесь `Preview ready`. Нужны Java 21 и установленные PostgreSQL tools; на этом компьютере они уже есть. При первом запуске Maven может скачать зависимости.
2. Откройте <http://127.0.0.1:8084/index.html> — витрина; <http://127.0.0.1:8084/control.html> — админка.
3. Логин и случайный начальный пароль записаны в **backend/data/preview/access.txt**. Этот файл и база исключены из Git. Не публикуйте их. Пароль можно поменять в профиле; начальный пароль при перезапуске не восстанавливается.
4. Выйти из аккаунта администратора можно кнопкой «Выйти». Для проверки покупателя откройте приватное окно браузера и зарегистрируйте отдельный проверочный аккаунт.

Остановка: **Stop-ARIA-Preview.cmd**. Товары, фото и заказы остаются в `backend/data/preview/postgres`. Для просмотра после остановки сначала снова запустите стенд. Выключение компьютера останавливает этот локальный адрес; на телефоне он не откроется. Для онлайн-staging нужен отдельный сервис с отдельной базой, его в этом этапе не создавали.

Не удаляйте `data/preview`, если хотите сохранить изменения. `mvn clean` удаляет тестовые отчёты в target, но не эту базу. Перезапуск работающего стенда без остановки не заменяет его сборку: для обновления сначала Stop, затем Start.

Из PowerShell можно задать другие пути к установленным инструментам:

```powershell
.\scripts\start-preview.ps1 -PostgresBin 'D:\PostgreSQL\bin' -JavaHome "$env:USERPROFILE\.jdks\ms-21.0.12.1"
```

Стенд слушает только 127.0.0.1; приложение 8084, отдельный PostgreSQL 55434. Он не использует адрес рабочей базы из окружения. Занятый порт не освобождается убийством чужого процесса — запуск остановится с объяснением.

## Включить настоящий AI

1. Ключ задаётся только серверу в исключённом из Git `.env.openrouter.local`: `ARIA_OPENROUTER_API_KEY=...`, `ARIA_OPENROUTER_MODEL=openrouter/free`. Действующий локальный файл сохраняется без изменений. После смены ключа перезапустите стенд. В Render ключ будет отдельной секретной переменной сервиса.
2. Админка → **ARIA Smart Pricing → Настроить режим и границы**.
3. Оставьте **RECOMMEND**. Включите разрешение отправки данных товара в OpenRouter и сохраните. По умолчанию отдельной новой базы это разрешение выключено; аудит включал его только на стенде.
4. На карточке нажмите **AI: выбрать стратегию**. Дождитесь окончания. **Источник AI** и название модели означают настоящий проверенный ответ. **ENGINE** означает расчёт Java или отказ внешнего провайдера; это не ответ нейросети.
5. Для помощника включите отдельное разрешение внешнего AI покупателям. На витрине покупатель дополнительно отмечает согласие перед запросом. Без этого работает подбор каталога.

Запросы ограничены дневными лимитами и паузой не менее минуты. Не нажимайте кнопку многократно. Бесплатный провайдер может быть недоступен или вернуть непригодный ответ; система сохранит ENGINE. Автоматического перехода к платной модели нет. Отсутствие истории продаж может обоснованно привести к «Сохранить цену».

Фоновый AI на локальном preview дополнительно выключен командой запуска. Изменения доступны только через ручные проверки; это предотвращает расход лимита во время бездействия стенда. Автопилот проверяется отдельно тестами, а не включается автоматически.

## Пройти сценарии вручную

### Товар, скидка и заказ

1. **Товары → Добавить товар**: уникальный SKU, название, категория, единица и базовая цена. Для примера 1 000 ₸; минимальная цена 650 ₸.
2. **Поступление**: номер партии, количество 12, закупка 600 ₸, текущая дата приёмки. Для продуктов обязательно укажите действующий срок годности.
3. **ARIA Smart Pricing**: прочитайте Java-сценарии, ограничения и уверенность; запросите AI. Если модель оставила цену, это допустимое решение. Для проверки скидки вручную нажмите **Изменить**, укажите допустимые 5% и причину. Не называйте ручную скидку выбором AI.
4. В приватном окне откройте карточку: цена должна стать 950 ₸. Зарегистрируйтесь как покупатель, добавьте две единицы в корзину, укажите свой проверочный адрес и оформите заказ. Сумма 1 900 ₸, остаток 10.
5. В админке **Заказы**: откройте состав, отправьте и доставьте заказ. Новый заказ можно отменить; списанные единицы вернутся в исходные партии. Отправленный заказ нельзя отменять как новый.
6. **История и результаты** показывает реальные изменения и отгрузки, а не фиктивный эффект кампании. При новой цене/партии/продажах старая рекомендация требует пересчёта.

### Социальная выдача

1. Создайте отдельный пригодный продукт с близким сроком и достаточным остатком. Откройте Smart Pricing и создайте социальное предложение, если риск сохраняется во всех допустимых сценариях. На этом шаге резерва нет.
2. **Анализы и документы** (`/admin.html`) → создайте учётную запись организации с отдельным паролем. В приватном окне войдите как организация, заполните заявку на проверку.
3. Администратор подтверждает организацию только после фактической проверки документов. В стенде используйте явно проверочные сведения; не выдавайте их за реальный фонд.
4. **Социальные заявки → Условия приёма**: регион, категории, хранение, минимальные дни до срока. Не выдумывайте условия настоящей организации.
5. Подтвердите предложение, организацию, количество и условия пригодности/перевозки. Теперь появится резерв. До завершения удерживается весь SKU, даже при передаче части количества — это ограничение существующей модели склада.
6. Организация может скачать акт. Только после фактической проверки и выдачи сотрудник нажимает **Социальная полка → Подтвердить выдачу**.
7. **Выдано организациям · CSV** содержит только фактические выдачи. Резервы и отмены не считаются передачами. Старые отдельные акты сохраняют прежний отчёт `acts.csv`.

### Конкуренты, помощник, поддержка

- **Цены конкурентов**: добавьте разрешённый HTTPS-источник, затем импортируйте CSV UTF-8 с заголовком `sku,barcode,unit,price,currency,observedAt,url`. Нужны совпадающие SKU, валидный GTIN, единица/упаковка, KZT и дата с часовым поясом. Пример файла последнего аудита — `target/e2e/competitors.csv`; это синтетические данные, не текущая цена реального конкурента.
- На витрине спросите «Товары до 2000 ₸», отметьте карточки для сравнения. Цены и доступность берутся из текущего каталога; себестоимость и контакты не передаются.
- **Поддержка**: отправьте сообщение, решив пример. Администратор найдёт его в **Сообщениях поддержки**, сможет отметить обработанным. Письмо автоматически не отправляется.

## Воспроизвести браузерные проверки

Проверки создают и изменяют только проверочные данные. Они разрешают адрес вида `http://127.0.0.1:порт`; запускать на рабочем сайте нельзя. Требуются Node.js и Playwright с Edge. Если Playwright не в стандартном поиске модулей, задайте `ARIA_PLAYWRIGHT_MODULE` абсолютным путём к установленному модулю.

```powershell
$previewConfig = Get-Content .\data\preview\config.json -Raw | ConvertFrom-Json
$env:ARIA_E2E_EMAIL = $previewConfig.email
$env:ARIA_E2E_PASSWORD = $previewConfig.password
node .\scripts\release-e2e.cjs
node .\scripts\maintenance-e2e.cjs
```

Первый тест требует настоящий AI-ответ и честно падает при ENGINE; это полезно для проверки подключения, но доступность внешней бесплатной модели не гарантирована. Между повторными AI-проверками выдерживайте лимиты. Отчёты, CSV, акт и снимки экрана сохраняются в `target/e2e`. Не запускайте изменяющие тесты одновременно на одной базе.

## Новые разделы платформы

Проверьте **ARIA AI Manager**, **Закупки**, **POS · продажи**, **Движения и потери**, **Интеграции**. Для настоящего AI нужно согласие отдельно в Smart Pricing и политике менеджера; инструкция со всеми шагами: [AUTONOMOUS_MANAGER.md](AUTONOMOUS_MANAGER.md). Стенд после аудита оставлен с выключенным менеджером и внешним AI; включение требует решения администратора. Секреты остаются серверными.

Кнопка установки создаёт браузерную PWA. Для просмотра с телефона через интернет понадобится отдельно согласованный HTTPS staging; адрес 127.0.0.1 с другого устройства не откроется. Основной Render этой веткой не переключён.
