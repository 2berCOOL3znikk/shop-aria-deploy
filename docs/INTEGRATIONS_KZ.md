# Интеграции Казахстана — проверено 29.10.2026

Приоритет KZT, одинаковые SKU/GTIN, единицы/объём и регион. API продавца не считается публичным API мониторинга. Отсутствие найденной документации не доказывает отсутствие партнёрского API.

- **Kaspi.kz:** [официальный раздел товаров API](https://guide.kaspi.kz/partner/ru/shop/api/goods) описывает добавление и характеристики собственных товаров продавца. Он не подтверждает право или техническую возможность массово получать цены конкурентов. Сейчас — разрешённый CSV; для адаптера нужны письменные условия/документация разрешённого источника цен и доступ именно к нему.
- **Magnum:** проверены [сайт](https://magnum.kz/) и [официальный раздел поставщиков](https://corp.magnum.kz/ru/suppliers). Каталог/портал поставщиков не равны общедоступному API мониторинга. Нужен согласованный экспорт или партнёрская документация с регионом и условиями использования.
- **SMALL:** [официальный сайт](https://small.kz/) при прямой проверке вернул 403. Подтверждённая публичная документация мониторинга не найдена в проверенных официальных материалах. Ограничение не обходилось. Нужен разрешённый CSV/партнёрский поток.
- **Arbuz.kz:** [официальный сайт](https://arbuz.kz/) не предоставил подтверждённой публичной документации API цен в проверенных страницах. Нужен согласованный источник и условия хранения/частоты/использования цен. Работает CSV.

`CompetitorImportAdapter` отделяет происхождение данных от существующей строгой проверки CSV. Фактически реализован `CsvCompetitorAdapter`. Сетевые адаптеры маркетплейсов не включены; CAPTCHA, закрытые API и ограничения сайтов не обходятся. Пример колонок и правила — [SMART_PRICING.md](SMART_PRICING.md). Синтетические CSV в тестах явно помечены проверочными, не выдаются за рынок.

## Poster POS — основной внешний вариант

[Документация](https://dev.joinposter.com/) и [официальное руководство интернет-магазина в репозитории Poster](https://github.com/joinposter/docs/blob/master/en/market/guidelines/e-commerce.md) описывают отдельный `access_token` персональной интеграции; для приложения нескольких клиентов — OAuth.

Подготовлен `ExternalPosAdapter` и `PosterPosAdapter`: заданный состав продажи + явная таблица внутренних productId к Poster product_id → план сопоставления KZT. Проверяется формат переданных ID; существование внешнего товара и соответствие SKU без доступа к Poster не проверяются. Нет HTTP-клиента, отправки, обещания API-совместимого фискального чека или установленного подключения. `sent=false`, `fiscal=false`. Полноценный внутренний POS работает независимо.

Для настоящей интеграции нужны: разрешение владельца Poster-аккаунта, отдельный токен с минимальными правами (через серверный секрет), account/точки/склады, действительный каталог и product_id, выбор направления синхронизации, тестовый аккаунт/режим без финансовых последствий, правила повторов и сверки. Сначала чтение и проверка сопоставления; запись — только после отдельного разрешения. Возможность бесплатного доступа конкретного аккаунта ещё не подтверждена; платные подключения не создаются.

## iiko — резерв

[Актуальная официальная авторизация](https://api.iiko.help/docs/concepts/authorization/) требует зарегистрированного приложения `appId`, `clientSecret` и организационного `apiKey`, затем обмена на ограниченный по времени Bearer-токен. Это отдельные учётные данные. До выбора iiko нужны доступ организации, права/стоимость API, точки и каталог, тестовые данные и направление синхронизации. iiko пока не подключён.

Ключ формата OpenRouter используется только сервером OpenRouter; он не является ключом Poster, iiko или Kaspi. Значения секретов в этот документ, браузер, Git и журналы не записываются. Не присылайте их в CSV.
