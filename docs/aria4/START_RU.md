# ARIA: открыть проверенную локальную версию

**Онлайн:** [отдельный staging](https://aria-v4-staging-2ber.onrender.com/start.html), `backend/ARIA-Staging-preview.cmd`. Доступы — `backend/data/staging/access.txt`, [инструкция](STAGING_RU.md). Локальные сценарии ниже сохраняются; основная production-версия не переключалась.

1. Дважды нажмите **ARIA.cmd** в `D:\Projects\ARIA\ARIA-agent2`. При первом старте дождитесь сборки. Откроется [старт ARIA](http://127.0.0.1:8089/start.html).
2. Для просмотра уже подготовленной **учебной** компании нажмите **ARIA-preview.cmd**. Отдельное окно Edge войдёт настоящим учебным владельцем через обычную форму. Пароль хранится шифрованным, не попадает в ссылку или Git. Закрытие окна завершает просмотр, а не удаляет данные.
3. Обычный вход использует **email и пароль ARIA**. Доступы WooCommerce вводятся позднее в «Мои магазины». Кнопка «Продолжить» появляется только после проверки действующей сессии сервером.

Для обновлённого каталога с готовыми карточками — **ARIA-Catalog-preview.cmd**: отдельный демонстрационный магазин, [инструкция](PRODUCTS_RU.md). Для проверенного автономного цикла и сохранённого AI-решения отдельного учебного WooCommerce — **ARIA-AI-preview.cmd**, [автономность и фактические цены](AUTONOMY_RU.md), [AI/путь товара](AI_AND_FLOW_RU.md). Каждый просмотр использует собственный вход; токены между компаниями не передаются.

В меню компании доступны версия/среда/соединение, аккаунт, выход и завершение всех собственных сеансов. Последняя команда немедленно отзывает старые токены этой компании. Язык и тема сохраняются. Переход между отдельными окружениями не пересылает токены.

## IntelliJ

Выберите конфигурацию **ARIA — запуск** и зелёный треугольник. Она запускает небольшой подготовленный JAR, независимый от прежнего неполного Java-модуля. Один обычный запуск `ARIA.cmd` создаёт его и устанавливает конфигурацию в контейнер проекта, сохраняя остальные настройки IDE. Исходный Spring Boot main остаётся прежним.

## Что проверено 11.11.2026

- Реальный запуск из остановленного состояния: PostgreSQL и три отдельные службы; 61,49 с на этом ПК. Повторный: 7,3 с, прежние процессы и данные. Два одновременных старта корректно ожидают друг друга.
- 32 затронутых серверных теста на PostgreSQL V1–V34: сессии, права, изоляция, заявки и активация. Полный ранее сохранённый прогон — 276; новые общие проверки выполняет CI, их результат фиксируется отдельно.
- 60 видов старт/вход/кабинет: RU/EN, светлая/тёмная тема, 360/390/768/1024/1440 px. Неверный пароль, задержка настоящего ответа без повторного входа, возврат в нужный раздел, устаревший токен, выход, покупательская CAPTCHA и чужой issuer проверены в браузере.
- Данные компании, владельца, заявок и прежние строки аудита сохранены при перезапуске; добавились две законные записи запуска.

Доказательства: [браузер](evidence/p0-e2e.json), [запуск](evidence/launch-smoke.json), [двойной старт](evidence/double-start.json), [серверные тесты](evidence/p0-targeted-tests.json). Скриншоты «до» и P0 находятся в той же папке. Это ещё не новый дизайн содержимого главной: он следующий в едином плане.

## Границы

Это подготовленная локальная среда данного ПК, не универсальный установщик. Нужны Java 21, Node.js 20+, существующий PostgreSQL и закрытые настройки. ПК должен быть включён. Запускатель не сбрасывает пароли, не подменяет компанию демо и не трогает старые порты 8084/8085. Логи ошибок — закрытая `backend/data/desktop`; не отправляйте папку с настройками публично.

Учебная компания «Север» пустая; внешние запросы отключены настройкой сервера. Её сохранённые флаги не изменялись этим этапом. Прежние WooCommerce и реальный OpenRouter KEEP принадлежат отдельной учебной компании; новых AI-запросов этот этап не выполнял. Забытый пароль, индивидуальный список сеансов, вход в несколько компаний и облачное предоставление окружений ещё не готовы. Основной Render, main и рабочая база не изменялись.
