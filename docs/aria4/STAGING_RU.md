## Изоляция и сохранность

Отдельный Render Free `aria-v4-staging-2ber`, Frankfurt, ветка `codex/production-foundation`, автодеплой выключен. Основной `shop-aria` на `main` не переключается. Для нового staging создан отдельный проект Neon **ARIA 4 Staging**, `dawn-dew-85661116`, база `aria_staging`, собственная роль и binding. Рабочие строки, контакты, доступы WooCommerce и ключи OpenRouter не копировались.

Staging проверяет точный сервер, БД, роль и компанию **до Flyway**; случайное подключение другой базы останавливает запуск. Миграции V1–V36 применены только к выделенной среде. Изначально пустая база сейчас содержит только явно учебные записи проверки: основной остаток 12, закрытые проверочные партии/фото, два отключённых сотрудника и неподтверждённый партнёр. Две явно учебные заявки проверки закрыты, учётные записи по ним не создавались. Продаж, активных внешних подключений, внешнего AI и реальных передач товара нет. Учебные данные сохранились после обновлений сервера.

[Прежний реальный автономный цикл](AUTONOMY_RU.md) остаётся отдельной учебной средой: KEEP модели не подменяется, эксперимент/откат не повторялись. В новую компанию ключ и согласия не перенесены.

## Проверка и выпуск

Публичный вход и экраны 390/1440 px, доступ сотрудника/партнёра и запреты проверены браузером. Сохранены скриншоты и целевые PostgreSQL-проверки; полный набор выполнен в успешном CI каждого этапа. Финальная проверка `scripts/staging/final-online-review.cjs` после входа использует только GET; не создаёт приглашения, партии, компании или согласия.

`scripts/staging/start-local.ps1` нужен только для разработки. Пользователю публичной версии не требуются локальные порты или включённый компьютер. Бесплатный Render может засыпать; во время сна автономные задачи не выполняются. Искусственных пингов, платных workers/cron/дисков и повышения тарифа нет. Постоянные данные находятся в отдельном Neon.

Перед production нужны свежая репетиция backup/restore V36, совместимый откат, критические сценарии и зелёный CI, затем отдельное разрешение владельца. Код без WAREHOUSE нельзя просто вернуть поверх базы с такими сотрудниками. Никаких изменений production этот этап не разрешает.
