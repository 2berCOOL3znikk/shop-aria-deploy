# Текущий этап P5: автономный подключённый магазин

Основа `3e74bd0`, рабочая ветка `codex/production-foundation`. P0–P4 не повторять. Производственные среды и другие компании не изменять.

Обнаруженные разрывы: очередь обновления не выполняет повторяющийся полный цикл; фоновый внешний анализ зависит от OpenRouter; разрешённый Java fallback не может применить изменение; настройки запуска специально отключают учебные worker. Внешний автопилот без подтверждённых партий допускает только отдельно подтверждённые бессрочные товары. Это ограничение сохраняется.

Реализация: существующая StoreSyncQueue получает одну долговечную задачу AUTONOMY на магазин. Короткие транзакции вокруг HTTP, проверка аренды/поколения до каждой фазы, ограниченные повторы, сохранённое следующее время, пауза/остановка. Последовательность: каталог → заказы → факты/анализ → допустимый AI или явно разрешённый ENGINE → запись → readback → история. Неподтверждённый PUT не повторять, а сверять.

Доступы и согласия раздельные: расписание, внешняя модель, запись цены, категории/минимум/предел/интервал, отдельное разрешение малых низкоуверенных экспериментов. Базовый Java KEEP не выдавать за доказанный эффект скидки. Если модель выбрала KEEP или требует человека — не подменять её решение экспериментом. Контролируемый ENGINE-эксперимент разрешён отдельно, ограничен 5% и границами владельца, зависит от покрытия запаса/истории/неопределённости, без обещания роста. Один эксперимент до проверки результатов; никаких вымышленных сроков или обучения ML.

Проверка: отдельные явно учебные товар и история в уже разрешённом локальном WooCommerce; прежние три позиции и сохранённый OpenRouter KEEP не менять. Не изменять даты старых заказов. Новую синтетическую историю явно обозначить учебной, не коммерческим спросом. Показать настоящий автоматический PUT/readback и безопасный откат, источник ENGINE/AI, исключения, сохранение после перезапуска. Модель KEEP не форсировать.

Затем: целевые критические тесты, браузер, commit/push/CI; оставшиеся разделы и бесплатный отдельный staging. Этот файл описывает работу в процессе, а не утверждает её завершение.
