# UX-проверка ARIA · 15.11.2026

Работа продолжается в `codex/production-foundation`. Исходный HEAD — `32a6743`. Production и данные существующих компаний не изменялись.

## Этап 1 — навигация и закрытая витрина

- Один компонент меню для компании, товаров, склада и магазинов: выбор, клик снаружи, Esc, клавиатура, смена раздела, Back. Обычные раскрываемые пояснения сохраняют состояние.
- Старая вкладка очищает частные данные при смене любого аккаунта, включая пользователя той же компании. Новый вход другой вкладки сохраняется.
- Владелец: **Открыть витрину → товар → Вернуться в кабинет**. Каталог, характеристики, отзывы и наличие запрашиваются с собственным сеансом. Частная компания не превращается в публичный магазин.
- У постороннего — понятное приглашение войти; у партнёра нет предпросмотра каталога владельца. При ошибке больше не остаётся вечная загрузка.
- Непроверенное подключение предлагает завершить настройку, а не сообщает о подключённом магазине.

Проверки: 8 групп браузерного контракта меню; 5 сценариев контракта витрины; 12 проверок привязки сеанса; 2 целевых теста Java на новой локальной PostgreSQL (все прошли). Контрактные данные не являются внешним E2E. В настоящем Edge новое оформление с реальным API staging загрузило товар «Кухонное полотенце», его карточку и обратный переход, без ошибок API/JavaScript. Это проверка локальных файлов интерфейса, публикация проверяется отдельно.

## Следующий этап

1. Партии и сроки: выбор товара, фото, остаток и статус, активные партии по умолчанию без сокрытия просроченных.
2. Категории из настоящего каталога в настройках AI и цен, без ручного перечисления и без расширения разрешений.
3. Честные раздельные состояния модели и автоматических расчётов, исправление ссылок AI.
4. Короткая помощь, интерактивные шесть шагов, проверки RU/EN/телефона/тем и ролей.

Реестр причин и состояния — `ISSUES_RU.md`. Записи/скриншоты с рабочим сеансом хранятся только в исключённой из Git папке; секреты в доказательства не включаются.
