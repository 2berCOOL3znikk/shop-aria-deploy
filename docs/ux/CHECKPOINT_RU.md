## Этап 1 — навигация и закрытая витрина

- Один компонент меню для компании, товаров, склада и магазинов: выбор, клик снаружи, Esc, клавиатура, смена раздела, Back. Обычные раскрываемые пояснения сохраняют состояние.
- Старая вкладка очищает частные данные при смене любого аккаунта, включая пользователя той же компании. Новый вход другой вкладки сохраняется.
- Владелец: **Открыть витрину → товар → Вернуться в кабинет**. Каталог, характеристики, отзывы и наличие запрашиваются с собственным сеансом. Частная компания не превращается в публичный магазин.
- У постороннего — понятное приглашение войти; у партнёра нет предпросмотра каталога владельца. При ошибке больше не остаётся вечная загрузка.
- Непроверенное подключение предлагает завершить настройку, а не сообщает о подключённом магазине.

Проверки: 8 групп браузерного контракта меню; 5 сценариев контракта витрины; 12 проверок привязки сеанса; 2 целевых теста Java на новой локальной PostgreSQL (все прошли). Контрактные данные не являются внешним E2E. В настоящем Edge новое оформление с реальным API staging загрузило товар «Кухонное полотенце», его карточку и обратный переход, без ошибок API/JavaScript. Это проверка локальных файлов интерфейса, публикация проверяется отдельно.

## Этап 2 — партии и понятный AI

Склад открывает «Партии и сроки»: выбор товара, собственное фото/placeholder, количество/срок/статус; в списке по умолчанию партии с остатком, включая просроченные. Поиск подписан, ближайший срок — начальная сортировка. Из карточки товара ссылка ведёт прямо к его партиям.

Все четыре формы AI/цен используют один выбор категорий. Нативные категории — из каталога; для внешнего магазина доступны фактически подтверждённые категории владельца (WooCommerce-снимки пока не хранят категории). Старые выбранные значения сохраняются явно; пустой выбор не даёт права автоматического изменения. Бюджет и период AI перенесены в дополнительные параметры.

AI показывает OpenRouter, автоматический Java-расчёт, отсутствие локальной модели и состояние фоновых проверок раздельно. Нет фиктивных запросов к модели: на этом staging OpenRouter не настроен. Непроверенный магазин ведёт к подключению вместо «Возобновить». Сервер также запрещает включение автономности до подтверждения подключения.

Целевые проверки: контракт категорий (4 группы), PostgreSQL — отказ неподключённому магазину и существующий положительный анализ рисков/социального черновика (2 успешных теста). В Edge пройдены выбор товара, партии, открытие партии, три шага AI-мастера; сохранение согласий и данных компании не выполнялось.

## Этап 3 — помощь в приложении

Постоянная ссылка «Помощь», короткие карточки реальных маршрутов и необязательное знакомство из шести шагов. Каждый шаг открывает раздел и выделяет доступный элемент. Есть пропуск, повторный запуск и возврат; предпочтение хранится отдельно для аккаунта и компании, без токена в ключе. Складскому сотруднику открывается только его справка.

Настоящий Edge с новым интерфейсом и API staging: все 6 шагов, завершение без смены маршрута, RU/EN, светлая/тёмная тема, 390 px, ссылка из помощи в партии — успешны. Записей данных/согласий нет. При первой попытке бесплатный сервер не успел проснуться за 30 секунд; повтор с ожиданием пробуждения завершён.

Закрытые загруженные фотографии теперь читаются с собственным сеансом, без ключей в адресах. Ответ от прежнего аккаунта не отображается; память освобождается при удалении карточек и уходе. Исходное изменение не исполнялось из-за лимита автоматической проверки. После восстановления лимита обычная проверка разрешила исправление; 3 целевых браузерных проверки фотографий успешны.
