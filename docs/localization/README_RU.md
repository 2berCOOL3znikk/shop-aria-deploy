# ARIA: RU/EN и проверенные сценарии

## Открыть новую версию

- [Закрытый учебный B2B-кабинет](http://127.0.0.1:8085/control.html#stores): компания `woo-e2e`, настоящее подключение WooCommerce и сохранённое решение OpenRouter. Вход — в локальном `data/woocommerce/aria-access.txt`.
- [Отдельная учебная витрина](http://127.0.0.1:8087/index.html): собственная PostgreSQL, справочный демокаталог ARIA и явно учебные цены/партии. Вход владельца — `data/localization-preview/access.txt`. Внешний AI здесь выключен.
- [Настоящий локальный WooCommerce](https://127.0.0.1:8449): вход — `data/woocommerce/access.txt`. Браузер может предупреждать о локальном сертификате; доверие добавлено только отдельной учебной Java-среде.

Адреса доступны на этом компьютере. Это локальные preview, не публичный staging. Прежний процесс 8084, main и production не обновлялись.

Из папки `backend` запустите `scripts/woocommerce/start-local.ps1`, затем `scripts/woocommerce/start-aria.ps1`. Для клиентской витрины — `scripts/localization/start-public-preview.ps1`. Нужен существующий локальный PostgreSQL на 55434. Скрипты сохраняют данные и не останавливают чужие процессы. Секреты хранятся в исключённой из Git папке `data` с ограниченными правами.

## Изменения

Переключатель RU/EN добавлен в боковую панель кабинета; в магазине используется переключатель навигации. Оболочка, 23 административных раздела, формы, WooCommerce-мастер, Smart Pricing, ARIA Impact, AI Control Center, клиентские страницы, помощник, ошибки и офлайн-экран используют явные текстовые ключи. Прежние маршруты, функции и обе темы сохранены.

Смена языка сохраняет маршрут и вход. Несохранённые данные формы требуют подтверждения; отмена оставляет введённое. Названия товаров, категории владельца, характеристики, сообщения покупателя и сохранённые объяснения не переводятся автоматически. Исходные объяснения помечены в английском интерфейсе. Это не подтверждение перевода коммерческих характеристик.

Исправлены:

- английские бюджеты, включая `2,000 KZT`, сравнение и фильтры скидок в помощнике;
- английский поиск с ограниченным явным словарём, без придуманных характеристик;
- язык проверочного примера регистрации, формат дат и английский PWA-манифест;
- сохранность исходного описания в редактируемой форме: оформление языка не попадает в данные;
- отдельный учёт учебных подключений и видимость сохранённого AI после перезапуска;
- недоступная регистрация и ссылки витрины в закрытой компании. Публичный `/api/auth/capabilities` сообщает только два логических признака; бизнес-API остаются закрытыми;
- офлайн-кэш: только фиксированные публичные ресурсы, без API, каталога, профиля и административных страниц.

## Подтверждённые проверки

`evidence/ui-audit.json`: 138 посещений — 23 раздела × RU/EN × 390/768/1440 px. `ui-audit-dark.json`: пять основных экранов тёмной темы на 390/1440 px. Проверяются ошибки JavaScript, переполнение и непереведённые системные подписи; исходные бизнес-данные исключены явно.

`evidence/functional-e2e.json`: реальное учебное создание товара с Java SKU, точная сохранность описания, отмена смены языка в несохранённой форме, открытие сохранённого настоящего AI-решения, регистрация покупателя, корзина между вкладками без дублей, сумма, проверка адреса и удаление, английский поиск и сравнение по настоящему каталогу, отказ от написания кода, 44 клиентские страницы RU/EN на двух размерах и настоящий офлайн-переход. Заказ не отправлялся; согласия и разрешения не включались. Поиск помечен ENGINE: эта проверка не является внешним AI-запросом.

`../connected-commerce/evidence/java-tests.json`: полный прогон 240 серверных тестов на новой PostgreSQL с V1–V32, 0 ошибок, падений и пропусков. `company-isolation-v32.json`: повторная проверка двумя процессами и базами после изменения входа. WooCommerce E2E, ценовая запись и настоящий OpenRouter подтверждены отдельными доказательствами предыдущих завершённых этапов.

Снимки RU/EN, мобильного магазина, помощника и тёмной темы находятся в `evidence`. Снимки прежних UX-этапов сохранены в `../experience/evidence` и `../rubezh2/EVIDENCE`; показатели разных учебных запусков не следует сравнивать как коммерческую динамику.

`visual-ready.json` дополнительно подтверждает готовность каталога RU/EN на 390/1440 px: реальные карточки отрисованы, загрузочный экран отсутствует. Снимки каталога сделаны после загрузки видимых изображений; большинство справочных товаров пока имеют честные нейтральные placeholders, а не неподтверждённые фотографии.

Следующая завершённая итерация — `product-cards.json`: пищевой товар, бытовой товар и текстиль на двух языках и двух размерах, плюс тёмная мобильная карточка. Пустые таблицы скрыты; названия полей источников переведены, значения сохранены; сведения магазина помечены отдельно. Единица остатка берётся из товара, даты срока показаны с названием месяца. Чтение карточек не изменяет данные. Для части товаров по-прежнему нет разрешённых фотографий; нейтральная заглушка не содержит надписи на другом языке.

## Поддержка переводов

`js/app-copy-data.js` связан с явными вызовами и атрибутами. Автоматического перевода всех текстовых узлов страницы нет. Обход DOM прежним переводчиком отключён на новых страницах.

Правьте `scripts/localization/translations.en.json` и `system.en.json`, затем выполните:

```text
node scripts/localization/compile-copy.cjs --refresh-dictionary
node scripts/localization/check-copy.cjs
```

Обновление словаря работает на чистой копии репозитория без модели и временных снимков. Проверка не требует зависимостей: синтаксис 43 клиентских скриптов, существование ключей и сохранность параметров шаблонов. Она включена в GitHub CI.

Первоначальный режим `--reapply-from-snapshot` — инструмент однократного преобразования этого этапа, а не штатный способ изменения готового интерфейса. Локальные исходные снимки не поставляются; не запускайте этот режим поверх последующих ручных изменений. Необязательные Python-инструменты переводят только статические фразы локально. Модель и её зависимости не входят в приложение. Черновой машинный перевод требует проверки терминологии и UI.

Браузерные сценарии используют Playwright из `ARIA_PLAYWRIGHT_MODULE` и установленный Edge. `functional-e2e.cjs` допускается только в двух указанных учебных средах: он создаёт учебный товар/партию и аккаунт, меняет его корзину. Заказ и запрос OpenRouter не отправляются.

## Ограничения

Самостоятельная регистрация компаний не реализована: оператор подготавливает отдельный процесс и БД на компанию. Регистрация покупателя не создаёт бизнес.

Настоящее сохранённое решение OpenRouter в `woo-e2e` — KEEP 1215 ₸. Подтверждённая запись 1350 → 1215 ₸ была отдельно разрешённой владельцем операцией, а не скидкой, выбранной этой моделью. Тестовые ответы модели в JUnit проверяют ограничения, но не доказывают живой автономный запуск скидки.

Самостоятельное подключение компаний, полный набор характеристик всех категорий и проверка магазина реального владельца остаются этапами. Для внешнего WooCommerce нужны его домен, разрешённые доступы и публичный HTTPS ARIA для уведомлений. Ключи не отправлять в чат. Согласие на ценовой AI действует только в учебной компании; покупательский внешний AI здесь не включён.
