# ARIA Manager: работа и ограничения

Актуальное продолжение: [постоянная очередь, индивидуальные горизонты, V17–V18 и новый Control Center](AUTONOMOUS_PLATFORM.md). Настоящий срок годности, покрытие запаса, горизонт прогноза и срок пересмотра — отдельные величины; универсального прогноза на 14/30 дней нет. Длина 14 дней ниже относится к проверке качества модели на истории, а не к длительности скидки.

Продолжение существующего ARIA Shop, а не отдельное приложение. Java проверяет решения и проводит все операции с ценой и остатком. OpenRouter выбирает только допустимые сценарии. Миграции V1–V11 сохранены; V12–V16 добавляют менеджер, закупки, внутренний POS, социальную логистику и журнал движений.

## Начать проверку

Запустите `Start-ARIA-Preview.cmd`, откройте http://127.0.0.1:8084/control.html. Учётная запись стенда — в исключённом из Git `data/preview/access.txt`. Подробности: [PREVIEW_GUIDE.md](PREVIEW_GUIDE.md). Стенд использует отдельную локальную PostgreSQL, без рабочей Neon/Render.

1. **Товары → Добавить товар:** название, уникальный SKU, единица, цена и минимальная цена, штрихкод при наличии. Минимальный остаток задаётся владельцем. Затем **Поступление**: реальная партия, закупка, количество, сроки. Продукты без срока не принимаются.
2. **ARIA AI Manager:** начальный режим `ADVISOR`, внешний автоматический AI выключен. Менеджер сам формирует исключения по остаткам, срокам, динамике отгрузок и ценам. На Free проверка запускается при реальной активности API магазина. Кнопка «Проверить сейчас» нужна для проверки, а не для повседневного управления.
3. Для настоящего AI сначала задайте серверный `ARIA_OPENROUTER_API_KEY` и бесплатную модель в соответствии с [OPENROUTER.md](OPENROUTER.md). В **Smart Pricing → Настройки** разрешите ранее согласованный состав данных и дневной лимит. Затем в **Manager → Настроить** отдельно разрешите автоматические обращения. Данные клиентов не передаются. Без этих согласий доступен Java ENGINE, явно обозначенный в интерфейсе.
4. `ADVISOR` предлагает: администратор принимает, меняет или отклоняет скидку. `AUTOPILOT` требует отдельного подтверждения актуальных границ Smart Pricing. Минимальная цена, себестоимость/маржа, максимум скидки, категории и пауза обязательны. Низкая уверенность и ENGINE в цикле менеджера остаются на подтверждение. LLM не получает прямого доступа к записи цен.
5. **Экстренная остановка в Manager** отключает будущие циклы, автоматическое изменение цены и разрешения на внешний AI, включая помощника покупателя. Уже применённые цены не отменяются: используйте историю и отдельный откат. Уже отправленный сетевой запрос нельзя отозвать, но его результат не может примениться после остановки/смены настроек/истечения аренды. Кнопка остановки только ценового автопилота в Smart Pricing сохраняет разрешение на ручной AI и переводит активного менеджера в советник.

## Закупки

Создайте активного поставщика, затем **Закупки → Предложение поставщика**. Вносите только полученные условия: стоимость, минимальный заказ, срок поставки, дата и действительность, подтверждение сотрудником. Менеджер готовит черновики только при отдельном разрешении и достаточном дневном лимите; нулевой лимит запрещает их. Один открытый заказ на SKU. Создание черновика не меняет склад и не отправляет заказ/оплату поставщику.

**Разрешить приёмку** — внутреннее согласование. Если цена поставщика изменилась, отмените старый черновик и создайте новый. **Принять поставку** допускает частичные поставки; количество не превышает непринятый остаток. Повтор с тем же ключом создаёт одну партию. Отмена непринятого остатка сохраняет уже принятые партии. Внешняя отправка и платежи требуют отдельной интеграции и согласования.

## POS и склад

В **POS → продажи** введите SKU/штрихкод, используйте USB-сканер как клавиатуру или выберите товар. Камера работает только при наличии BarcodeDetector и разрешения браузера; ручной ввод остаётся доступен. При продаже сервер повторно проверяет цену и пригодность, списывает партии FEFO и создаёт внутренний чек с реальным заказом. Это не платёж и не фискальный чек.

При обрыве связи интерфейс сохраняет ключ и точный состав неподтверждённой попытки в текущем сеансе вкладки. Повтор использует тот же ключ. Не оформляйте ту же физическую продажу в другом окне до проверки истории. Полный возврат регистрируется в карантине, исключается из чистых отгрузок и не возвращает товар в пригодный остаток автоматически. Денежного возврата нет; физическая проверка и дальнейший учёт требуют сотрудника.

**Движения и потери** показывает приёмки, исправления, продажи, отмены, социальные выдачи, карантин и списания. Начальный снимок V16 — остаток в момент подключения журнала, не выдуманная история. Потери за 30 дней — только оформленные списания с известной закупкой; неизвестная стоимость показана отдельно. Просроченный ещё не списанный товар — риск, а не уже понесённая потеря.

## Социальные заявки

Менеджер может подготовить черновик при риске непроданного остатка. Он не резервирует товар. Сотрудник проверяет организацию, категорию, условия хранения/перевозки, пригодность и количество, затем подтверждает резерв. Для зарезервированной заявки доступны ответственный администратор, согласованная дата и последовательность **Запланировано → Готово → В пути**. Эти статусы не списывают товар. Только отдельное подтверждение фактической выдачи списывает запас и попадает в акт/отчёт. Просроченный товар запрещён.

## Как устроен прогноз

Используются реальные отгрузки SHIPPED/DELIVERED за доступные 90 дней, не заполненные вымышленными продажами. При короткой/нулевой истории прогноз отсутствует, пополнение опирается на минимум владельца. Базовый ориентир — средняя последних 7 дней. При достаточной истории ridge-авторегрессия с лагами 1/7 и средней 7 дней проверяется последовательным прогнозом следующего дня на последних 14 днях (backtest); выбирается лишь при улучшении MAE минимум на 10%. Это прогноз отгрузок с низкой уверенностью, без выдуманной эластичности и годовой сезонности. Потерянный спрос и история наличия неизвестны. 90-дневная аналитика остаётся локальной; состав отправляемых AI данных не расширяется сверх прежнего согласия.

## Free и PWA

Бесплатный Render может спать. На Free нет действий во время сна, фонового Web Push и гарантии непрерывного управления. Нет искусственных пингов для удержания сервера/Neon. Следующая реальная активность догоняет проверку; один цикл анализирует до 50 товаров и делает максимум одну AI-попытку. Курсор, дневные лимиты, исключения и журнал сохраняются в БД. Экземпляры конкурируют за общую аренду; устаревший исполнитель не применяет AI-цену.

«Установить ARIA» использует браузерную PWA: HTTPS в интернете, localhost для проверки. На iPhone — «Поделиться → На экран Домой». Это не опубликованное нативное приложение. Offline показывает только общую страницу; API, пароль, профиль, админка, каталог и формы не сохраняются сервис-воркером. Продажи офлайн не ставятся в очередь. Уведомления добровольные, при открытой ARIA. Обновление требует кнопки и подтверждения сохранения форм.

## Файлы и API

Расчёты: `DemandForecast`, `DemandAnalyticsService`; цикл/аренда/ограничения: `AiManagerService`, `ManagerStore`, `ManagerActivityConfiguration`; операции: `PurchaseService`, `PosService`, `InventoryLedgerService`, `SocialLogisticsService`; контракты: `service/integrations`. UI: `manager.js`, `purchases.js`, `pos.js`, `operations.js`, `pwa.js`, `platform.css`. Полный актуальный список изменений доступен в Git diff ветки.

Все новые API требуют ADMIN: `/api/admin/control/manager`, `/purchases`, `/pos`, `/movements`, `/integrations`, `/social-proposals/{id}/logistics`. Методы и DTO заданы соответствующими контроллерами. `/integrations/poster/prepare` готовит только план сопоставления: `sent=false`, `fiscal=false`, без сети и списания.
