# Проверка платформы: продолжение после 2cb3d78

Рабочая ветка — `codex/production-foundation`. Main, production Render, рабочая база и согласия компаний не менялись. Учебные процессы 8085/8087 и установленный WooCommerce 8449 изолированы; прежний 8084 сохранён.

## Исправленные сценарии

- HTML-инъекция в старой админке: безвредное воспроизведение до/после, экранирование названия/SKU/категории. Новые нулевые учебные карточки восстановлены и архивированы. Коммит `91a6f72`.
- Кавычки/обратные слеши в профиле и корзине; явная ошибка чтения заказов и повтор GET без повторной отправки заказа. Проверены RU/EN.
- Сетевой импорт больше не удерживает транзакцию и блокировку магазина. Отключение и смена ключей завершаются до ответа поставщика. Перед применением проверяются версия/доступы/задание и снимок каталога; более свежая цена сохраняется. Коммит `3f774ed`.
- На телефоне история обновления показывает результат и причину в карточках. Подписи и подсказка прокрутки переведены; серверный статус неприменённого ответа имеет понятное объяснение.
- Оболочка ждёт завершения загрузки раздела. Исправлено преждевременное `aria-busy=false`, которое позволяло быстрому аудиту снимать промежуточный экран. Устаревший ответ при переключении не заменяет новый раздел.
- Включено HTTP-сжатие HTML/CSS/JS/SVG от 2 КБ; JSON API и бинарные файлы исключены. [Настройки Spring Boot](https://docs.spring.io/spring-boot/how-to/webserver.html#howto.webserver.enable-response-compression). Зависимости не обновлялись.

`route-readiness-before.json` / `after.json` — задержан настоящий авторизованный GET Dashboard, проверены ожидание и быстрый переход на другой раздел RU/EN. Снимок before — диагностическое воспроизведение, не готовый Dashboard.

Нет ошибок JS, горизонтального переполнения страницы или непереведённых системных текстов. Исходные бизнес-названия/объяснения исключаются явно.
