# ARIA Shop

ARIA Shop — демонстрационный интернет-магазин и система учёта товарных остатков для Казахстана. ARIA анализирует сроки годности, скорость продаж и маржу; сотрудник магазина проверяет рекомендации, фонд бронирует опубликованный лот, а система формирует черновик акта передачи.

## ARIA Control

После входа администратор открывает `/control.html`. Здесь находятся товары, поставщики, складские партии, сценарии скидок, заказы, социальные предложения, журнал и инструкция «Как работать». Прежняя `/admin.html` остаётся разделом анализа, проверки организаций и документов.

- Создать товар → принять партию → проверить каталог. Без пригодного остатка товар скрыт.
- У партии отдельные даты, остаток, себестоимость и поставщик. Продажи списывают пригодные партии по FEFO.
- Скидка рассчитывается до применения. Показаны новая цена, прибыль, маржа, предел без убытка. Скидка действует на весь SKU. 0% отменяет её. Себестоимость — максимальная по пригодным партиям.
- Бронь фонда удерживает SKU, но не считается выдачей. Фактическую передачу подтверждает администратор. Повторное подтверждение блокируется.
- Отмена нового заказа возвращает товар в исходные партии. Просроченная или закрытая партия не становится автоматически пригодной.
- Все изменения управления фиксируются в журнале. Связанные записи архивируются или закрываются с причиной; история не стирается.

Полные инструкции: [демонстрация](docs/DEMO.md), [API](docs/API.md), [архитектура](docs/ARCHITECTURE.md), [границы реализации](docs/SCOPE.md).

## Проверка

```powershell
.\mvnw.cmd clean verify
```

Проверяются HTTP-права, три связанных ресурса, FEFO, истечение сроков, границы скидок, изменение цены в корзине, возврат исходных партий, отдельное подтверждение социальной выдачи и два одновременных оформления одной корзины. Интеграционные тесты используют отдельную H2 в памяти и не трогают локальную базу.

В PostgreSQL схема управляется Flyway (`V1`, `V2`), Hibernate проверяет её через `validate`. `V1` создаёт новую схему или принимает прежнюю схему Hibernate без удаления таблиц. Перед обновлением существующей базы сделайте резервную копию; конфликтующие SKU требуют ручной сверки. Исторические стоимости, которые не были сохранены прежней версией, не восстанавливаются предположениями.

## ARIA Intelligence

Без ключа показывает честно обозначенную сводку Java. `ARIA_OPENROUTER_API_KEY` и необязательная `ARIA_OPENROUTER_MODEL` подключают объяснение OpenRouter по агрегированным количествам. Имена покупателей, контакты, токены и цены закупок наружу не отправляются. Модель не получает инструментов записи. При недоступности провайдера сохраняется сводка правил.

Для обычного запуска Maven переменные задаются в PowerShell; `.env` автоматически читает Docker Compose, а не Spring Boot.

## Локальный запуск с PostgreSQL

Нужен Docker Desktop. Из папки `backend`:

```powershell
Copy-Item .env.example .env
# Откройте .env и задайте собственные пароли
docker compose up --build
```

Откройте [http://localhost:8080](http://localhost:8080). PostgreSQL хранит данные в томе `aria_database`, поэтому они переживают перезапуск контейнеров. Остановить приложение: `Ctrl+C`; затем `docker compose down`. Чтобы также удалить локальные данные: `docker compose down -v`.

Первый `--build` скачивает базовые контейнеры и Java-зависимости; подготовьте сборку заранее на сети с доступом в интернет. После этого показ приложения, база и иллюстрации работают локально без интернета университета.

Для показа на ноутбуке без интернета университета подключите компьютер и телефон/другой ноутбук к одной локальной Wi-Fi сети или точке доступа телефона. Узнайте IPv4 ноутбука командой `ipconfig` и откройте на втором устройстве `http://<IPv4-ноутбука>:8080`. Если Windows спросит о сетевом доступе, разрешите входящие подключения для частной сети. Некоторые университетские Wi-Fi сети изолируют устройства друг от друга — в таком случае используйте точку доступа телефона. Каталог и иллюстрации встроены в приложение и не требуют внешних картинок или шрифтов.

### Быстрый запуск без Docker

Требуется Java 21. Из папки `backend`:

```powershell
.\mvnw.cmd spring-boot:run
```

Локальный режим использует файловую H2: данные сохраняются в `data/aria.mv.db` относительно рабочей директории. Всегда запускайте из `backend`; в IntelliJ задайте эту папку в Working directory. Для защиты и публикации используйте Docker Compose с PostgreSQL. Не запускайте два экземпляра на одном файле H2; для отдельной проверки задайте `--spring.datasource.url=jdbc:h2:mem:qa`.

## Демо-роли

Локальный Compose по умолчанию создаёт:

| Роль | Логин | Пароль |
|---|---|---|
| Администратор магазина | `admin@aria.shop` | `admin123` |
| Покупатель | `user@aria.shop` | `user123` |
| Фонд «Тёплый дом» | `fund@aria.shop` | `fund123` |

Замените значения в `.env` перед показом в общей сети, включая `ARIA_JWT_SECRET` случайной строкой от 32 символов. Переменные администратора: `ARIA_ADMIN_EMAIL` и `ARIA_ADMIN_PASSWORD`. После входа администратор попадает прямо в ARIA-панель, фонд — на социальную полку, покупатель — в каталог. Администратор может создавать дополнительные учётные записи фондов и приютов в панели.

## Основной сценарий

1. Откройте каталог: поиск, категории, карточка с описанием, корзина и избранное. Покупатель оформляет заказ; остаток и заказ сохраняются в PostgreSQL.
2. Войдите администратором и запустите анализ. Этапы показываются во время выполнения; результат появляется после ответа сервера. Кандидаты включают медленно продающиеся, близкие к сроку годности, с низкой маржой и отклонением от демонстрационной рыночной цены.
3. Выберите конкретные строки для акта. Срочные позиции заранее отмечены, остальные добавляются вручную. Кнопка создаёт отдельную партию и скачивает HTML-черновик акта. История партий доступна в панели. Просроченный товар нельзя передать через социальную полку.
4. Опубликуйте допустимую партию на социальной полке. Товар временно исчезает из обычной витрины, чтобы его не продали параллельно. Фонд входит под ролью организации, видит предложение, бронирует его; бронь удерживает SKU от продаж, а остаток уменьшается после отдельного подтверждения фактической выдачи в ARIA Control. Организация скачивает свой черновик акта с количеством и стоимостью.
5. В панели доступны сводные показатели, диаграммы категорий и статусов, журнал анализов, история актов, предложения скидок, списание конкретной позиции и загрузка фото товара (JPEG/PNG, до 5 МБ).

Правило выдачи: критические товары с годностью до 7 дней предлагаются сразу; обычные позиции можно объединить в одну подтверждённую сотрудником партию и согласовать одну выдачу. Резерв фонда подтверждает интерес и количество, но самовывоз согласуется сторонами отдельно. Автоматической отправки товара или поездки без подтверждения нет.

Цены каталога и отчётов показываются в тенге. Учебные исходные рублёвые цены преобразованы по официальному курсу 5,36 ₸ за 1 ₽ на 14.10.2026. Это фиксированный курс для стартовых демонстрационных данных, а не подключённый онлайн-конвертер. Новые цены вводите сразу в тенге.

## Публикация в Render и собственный домен

В репозитории подготовлен `render.yaml`: Blueprint поднимает Docker-приложение и PostgreSQL. Чтобы получить публичную ссылку:

1. Создайте Git-репозиторий и отправьте туда проект, выбрав папку `backend` корнем репозитория (в этой рабочей копии Git-корень находится именно здесь).
2. В Render создайте Blueprint из этого репозитория и задайте секреты `ARIA_ADMIN_EMAIL`, `ARIA_ADMIN_PASSWORD` и случайный `ARIA_JWT_SECRET` (не короче 32 символов) в настройках сервиса. Не используйте демо-пароли на публичном адресе.
3. После успешного развёртывания Render выдаст адрес вида `https://<service>.onrender.com`. Откройте его и проверьте `/actuator/health`.
4. Для домена добавьте его сначала в настройках Render. В Cloudflare DNS создайте CNAME для `www`, указывающий на имя сервиса Render, например `<service>.onrender.com`; на время проверки оставьте запись DNS-only. Для корневого домена используйте значение, указанное Render; Cloudflare поддерживает CNAME flattening для apex-домена. Дождитесь выпуска TLS-сертификата.

Render Blueprint и доменные записи здесь подготовлены как конфигурация; публичный сервис и домен появятся после подключения репозитория, учётной записи Render и прав на домен. Managed PostgreSQL в Blueprint использует платный план Render; перед созданием проверьте актуальную стоимость и доступность плана в своём аккаунте. Бесплатный веб-сервис может засыпать при простое.

## Границы текущего пилота

- Анализ и рыночные цены работают на учебных правилах и фиксированных исходных данных; внешние кассовые системы, маркетплейсы и живой валютный курс не подключены.
- Социальная полка доступна внутри приложения организациям с отдельной ролью. Внешняя отправка уведомлений фондам, курьерская логистика и платёжный эквайринг не подключены.
- HTML-акт — заполняемый черновик передачи с местами для подписей, а не утверждённая бухгалтерская или налоговая форма. Перед реальной передачей стороны сверяют реквизиты и требования своего бухгалтера.
- Для Render задайте собственные секреты и проверьте стоимость базы перед публикацией; локальные демонстрационные учётные записи для публичного сервиса выключены.

## Настройки

| Переменная | Назначение |
|---|---|
| `ARIA_DB_USER`, `ARIA_DB_PASSWORD` | Локальная база PostgreSQL в Compose |
| `ARIA_ADMIN_EMAIL`, `ARIA_ADMIN_PASSWORD` | Учётная запись администратора |
| `ARIA_JWT_SECRET` | Случайный секрет подписи JWT, минимум 32 символа; замените локальное значение перед публичной публикацией |
| `ARIA_SEED_DEMO_USERS` | Локальные аккаунты покупателя и фонда (`true` в Compose) |
| `ARIA_RESET_DATA_ON_START` | Пересоздать демонстрационные товары при старте; оставляйте `false` для обычного запуска |

## Стек

Java 21, Spring Boot, Spring Security/JWT, Spring Data JPA, H2 для быстрого демо, PostgreSQL для Compose/Render, HTML/CSS/JavaScript без внешних CDN.
